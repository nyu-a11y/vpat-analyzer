# V1 flow and state matrix

The interface is a projection of the request state machine, not an independent source of truth. Every asynchronous callback carries a stable `requestId`; a callback whose ID is not the active request is discarded before any DOM, focus, live-region, navigation, persistence, or export effect.

| State | User-facing content and actions | Focus and announcement | Allowed transition or recovery |
| --- | --- | --- | --- |
| Ready | Explain “one VPAT 2.5 Google Doc, DOCX, or searchable PDF from Google Drive” and where the private result will be created. Primary action: `Choose from Google Drive`. | Initial heading is first meaningful content. No unsolicited announcement on normal load. | Choose file; NYU access check may route to NYU access failure. |
| Validating | Show selected filename and `Checking file access and format…`; disable duplicate analysis submission. | Polite status announcement once. Keep focus stable unless validation reveals a blocking error. | Selected, inaccessible/unsupported, non-searchable PDF, or permanent validation failure. |
| Selected | Show literal filename, type, size, detected VPAT version and WCAG scope when known. Actions: `Analyze VPAT` and `Choose a different file`. | Move focus to the selected-file heading only when the selection action completes; announce readiness politely. | Processing or Ready with a replacement selection. A duplicate Analyze activation for the same active request is ignored. |
| Inaccessible or unsupported | State whether Drive access, file type, VPAT version, or eligible WCAG tables failed validation. Actions: `Choose another file` and contextual help. | Assertive error region; focus the error heading without trapping focus. | Ready/Validating after a new choice. |
| Non-searchable PDF | Say that the PDF appears scanned or has insufficient searchable text and cannot be analyzed because V1 does not use OCR. Action: `Choose another file`. | Assertive error; focus the error heading. | Ready/Validating only; never an OCR or image-to-AI fallback. |
| Processing: preparing source | Event-backed stage 1: `Preparing the source`. Explain that access and supported structure are being confirmed. Cancel is not promised. | Polite announcement when the stage event is accepted. Indeterminate motion respects reduced-motion; no percentage. | Extracting WCAG tables, retryable/permanent failure, or reload/resume. |
| Processing: extracting WCAG tables | Event-backed stage 2: `Extracting WCAG tables`. | Polite stage announcement; focus remains stable. | Checking coverage or a deterministic ingestion error. |
| Processing: checking coverage | Event-backed stage 3: `Checking criteria and coverage`. | Polite stage announcement; no repeated timer announcements. | Analyzing report quality or an incomplete/permanent failure. |
| Processing: analyzing report quality | Event-backed stage 4: `Analyzing report quality`. | Polite stage announcement; no provider/model jargon. | Preparing results, retryable provider failure, or permanent failure. |
| Processing: preparing results | Event-backed stage 5: `Preparing your Google Sheet`. This stage may consume immutable analysis output but must not imply that export succeeded until a receipt exists. | Polite stage announcement. | Success or export-only retry. |
| Retryable provider failure | Explain that analysis did not finish and no quality failure or grade was assigned. Action: `Try analysis again`; secondary action: choose another file. | Assertive error; focus the error heading. Retry restores focus to the accepted processing status. | Resume provider analysis within retry limits using the same request lineage, or choose another file. No partial score becomes F. |
| Permanent failure | Plain-language reason and safe next action. No quality grade. | Assertive error and error-heading focus. | Analyze another eligible file; support path if specified. |
| Export-only retry | Explain that analysis completed but the Google Sheet could not be created. Actions: `Try creating the Sheet again` and local `Save as PDF`; retain immutable analysis result and report-quality score. | Assertive error; focus the export error heading. Printing uses completed results and does not replace or mutate Sheet export state. | Retry export only. Do not re-ingest or reanalyze. Existing receipt yields Success rather than a second Sheet. Local PDF printing creates no export receipt. |
| Resume/reload | State that an unfinished request was found and is being reconciled. Do not claim background execution without a durable event/receipt. | Polite status. Focus the resumed state heading only after reconciliation. | Resume the next safe stage, show a retry state, show Success from an export receipt, or return Ready when no resumable record exists. |
| Success | `Your VPAT analysis is ready.` Make `Report quality: B (82%)` prominent for the completed fixture; show a nonzero review-count jump, the private-output location, and actions `Open Google Sheet (new tab)` and local `Save as PDF`. Present results in the three approved web review views while preserving and identifying the exact five Sheet tabs. Place `Analyze another` after the result workspace. | Assertive completion announcement once; focus success heading. The review-count control focuses `Items needing review`; `Analyze another` restores the Ready chooser. | Open the receipt URL, print a local copy from immutable completed results, or reset to Ready. Duplicate final callbacks cannot create or announce another export. |
| NYU access failure | Explain that an eligible NYU account is required and the app could not confirm access. No provider or file details. | Assertive error; focus access-error heading. | Retry sign-in/access through the approved deployment flow or leave. |
| Stale callback | No visible state. A request ID that is not active is rejected before effects. | No focus change and no live-region announcement. | None; retain the current active state. |

## Cross-state requirements

- All actionable controls provide at least a 44 by 44 CSS-pixel target and visible keyboard focus.
- Content reflows without horizontal page scrolling at 320 CSS pixels and at 200% zoom; data previews may use explicitly labeled, keyboard-accessible overflow regions only when unavoidable.
- Forced-colors mode retains control boundaries, focus, and status distinctions. Reduced-motion removes nonessential animation without hiding stage changes.
- Status is never conveyed by color alone. Filename, source remarks, provider evidence, and errors are rendered as text, never interpreted markup.
- Retry limits and permanent classifications are deterministic configuration. A retry never changes `requestId`; a new selected document creates a new request.
- The web app review navigator contains exactly `Summary`, `WCAG criteria`, and `Report quality`. It does not change the exported workbook's exact five-tab set or order.
- Browser printing may expose all completed views, unfiltered rows, evidence, scoring bands, and methodology for the print job, then must restore the prior interactive state. It creates no Drive file or export receipt.
- Owner-only VoiceOver, keyboard, focus restoration, reading order, 200% zoom/reflow, and visual comparison checks remain unchecked until manual acceptance.
